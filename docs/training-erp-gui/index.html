Installation and launch

Training ERP GUI is built with Python and PySide6. Use the installation instructions supplied with your copy of the application.

  1. Obtain the application. Check the project page for repository and release information.
  2. Check the release requirements. Confirm the supported operating system and, for a source distribution, the required Python version and dependencies.
  3. Keep the supplied files together. Preserve the directory structure for application modules, resources and example data.
  4. Follow the documented launch method. Use the entry point or launcher specified by that release.

A verified download link and release-specific installation commands have not yet been added to this guide.

Your first training session

  1. Choose one learning goal. Start with connection settings, IDoc configuration or a monitoring workflow.
  2. Prepare example data. Use the sample files supplied with your version, or an instructor-prepared copy with the expected structure.
  3. Open a relevant screen. Navigate through the application to the configuration or monitoring view used in your lesson.
  4. Explain the fields before changing them. Ask what each value represents and which part of the integration it describes.
  5. Record the outcome. Summarize what the learner can now explain and what still needs to be checked in a real system.

Use fictitious systems, partners and message identifiers so the same exercise can be repeated without exposing operational data.

Training scenarios

These exercises are discussion guides. They do not imply that an action in the training interface executes a transaction in a live SAP system.

1. Discuss connection settings

Learning goal: explain the purpose of a connection destination and distinguish its identifier from the settings it contains.

  1. Open the SM59-style training screen available in your version.
  2. Choose an example destination and identify the visible configuration fields.
  3. Ask the learner which values describe the intended remote system and which values would need verification.
  4. Write down the checks you would perform separately in an authorized test environment.

Expected outcome: the learner can explain the example configuration without treating the displayed values as proof of connectivity.

2. Walk through IDoc configuration

Learning goal: describe how destination, port and partner-profile concepts relate to an integration scenario.

  1. Define a simple fictional sender and receiver.
  2. Discuss the destination using the relevant connection screen.
  3. Open the WE21-style view and inspect the example port settings.
  4. Open the WE20-style view and discuss the partner configuration.
  5. Summarize the role of each configuration object in your chosen scenario.

Expected outcome: a short explanation of the configuration relationships and any questions to verify in the actual environment.

3. Practise a monitoring workflow

Learning goal: move from a question about a message to a focused set of results.

  1. Open an IDoc or proxy monitoring view provided by your version.
  2. Review the available selection fields and define what you want to find.
  3. Run the selection using the screen's execute action.
  4. Inspect the result table and identify the fields that would help you investigate further.
  5. Explain the next action you would take and the evidence you would need.

Expected outcome: a repeatable investigation approach using the example records.

4. Connect the interface to JSON data

Learning goal: understand how a desktop application can represent screen values in a configuration file.

  1. Choose a screen backed by JSON example data in your version.
  2. Make a copy of the corresponding file before the lesson.
  3. Compare the visible values with the fields in the JSON file.
  4. If that screen supports saving, change an example value and compare the resulting file.
  5. Explain which parts of this exercise describe the training application's storage rather than a real ERP backend.

Expected outcome: the learner can describe the relationship between interface inputs and stored example data.

Troubleshooting

The application does not start

Follow the launch method documented for your release. When running from source, check that the intended Python environment contains the required dependencies. Capture the actual error message before changing the setup.

No example records appear

Check your selection criteria and confirm that the expected example data files are present. Compare their location and structure with the release instructions.

A JSON file cannot be loaded

Check that the file is valid JSON and matches the expected structure. Restore your working copy if a manual edit introduced an error.

The screen differs from this guide

Check the application version and its release notes. The screen names in this guide describe training areas; available fields and actions can vary between versions.

Reporting a problem

Include the application version, operating system, affected screen, steps to reproduce, expected result and actual error message. Share only a minimal example that you are permitted to disclose.

Scope and limitations

Training ERP GUI is an independent educational project. It demonstrates selected integration concepts and screen workflows; it is not a complete ERP system or a replacement for practical experience in a real environment.

The presence of a transaction-style screen does not establish full functional equivalence with that transaction. Validate any live integration behavior separately.

This project is not an official SAP product and is not affiliated with or endorsed by SAP.
