Open Tpz Master / Migration review

Review mapping logic before a migration

Mustafa Alp · Tutorial · Updated 9 October 2026

Release v0.1.0

Before changing a mapping implementation, record what the existing mapping is expected to do.

The scenario

You are preparing a SAP PO mapping for a migration review. The aim is to identify transformation rules and open questions before implementation begins.

Build a review record

  1. Record the mapping name and the export you inspected.
  2. Choose important target fields and trace their displayed mapping trees.
  3. Record source dependencies, conditions and defaults visible in the graph.
  4. Flag custom logic or dependencies that need inspection in the original environment.
  5. Translate the findings into validation cases for the target implementation.

Use a simple checklist

Review area Question to record
Inputs Which source fields contribute to this target?
Conditions When should the value or target node be produced?
Defaults What is expected when an input is absent?
Dependencies Does this rule require further inspection outside the graph?
